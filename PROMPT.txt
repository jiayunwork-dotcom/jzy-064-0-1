海洋工程做波浪载荷预报，绕不开一个动作：把现场风况和一句「设计有效波高多少」翻译成一条能量沿频率分布的谱线。JONSWAP 谱就是干这件事的经典工具，可它的麻烦在于——设计者往往手里只有有效波高这个总量约束，而谱形里的尺度因子 α 藏在积分里，得反过来解才能让谱面积和给定波高对得上。请把这套 JONSWAP 频谱的正算与反演做成一个常驻的计算后端，让波浪载荷工具把风区、峰频与波高约束交进来，拿回一条自洽的谱线和它的统计矩。

谱形按 Hasselmann 给出的标准式组织：S(ω) = α·g²·ω⁻⁵·exp(−1.25·(ωp/ω)⁴)·γ^r，其中峰升因子的指数 r = exp(−(ω−ωp)²/(2σ²ωp²))，谱峰左右两侧的 σ 取不同定值（低于 ωp 用一个、高于用另一个），这两个常数与重力加速度在整个服务里钉死一份、各处引用同一套，不允许某个接口偷偷改成别的数。峰频 ωp、峰升因子 γ、风速这些量任一非正或 γ 小于 1 的，都要在进入谱计算之前挡下来、回一个带原因的错误结构。谱矩由数值积分得到：m0 = ∫S(ω)dω、m1、m2 依次是一阶二阶矩，积分上限要取到峰频的若干倍并随网格加密而稳定，不能积到一半就截断导致 m0 偏小。由矩派生的量包括有效波高 Hs = 4√m0、谱峰周期 Tp = 2π/ωp、以及跨零周期。

真正拉开实现水平的是波高约束这条反演路径。当调用方不直接给 α、而是声明「这条谱的有效波高应当等于某个值」时，服务必须迭代调整 α，直到由积分算出的 m0 满足 Hs = 4√m0 闭合到设定容差；只把标称波高写进返回、却拿一个没反演过的 α 去积分，会让声称的 Hs 和谱面积对不上，这正是要用测试焊死的地方。谱线上每个 S(ω) 采样点都要由上面的公式实算，禁止为了让曲线好看而写死一个尖峰形状。服务对外提供两件事：一是交入谱参数（或波高约束），返回谱采样点列、m0 到 m2 与 Hs、Tp；二是单独回一组谱矩与由矩导出的统计周期。谱参数可以按工况名字建档留存、日后凭名字取回复算，服务里自带一组有限风区的算例（γ 大于 1、峰确实落在 ωp 处、Hs 与 4√m0 能对上），谁拉起服务都能立刻拿它核对。不同工况并行提交时，各自的谱与矩各算各的，一份工况的中间量绝不能串进另一份的结果。

自动化测试要把下面这些因果关系逐条钉住：把 γ 从 1 加到较大值，同一 α 下峰更尖、峰值更高，而 γ 恰为 1 时谱形退化到 Pierson–Moskowitz 谱的形状；把 ωp 减半，能量整体向低频迁移、谱峰周期随之加倍；把波高约束加倍，反演出的 α 必须相应抬升使 m0 变为四倍；峰频取零或风速为负一律被拒。测试要专门盯住两处易错点——一是 ω 的幂次别把 ⁻⁵ 和 ⁻⁴ 写反导致谱在高频翘尾，二是波高反演后 m0 与 Hs 的闭合残差要落在容差内。

用 Python 3.12 搭配 FastAPI 实现，把谱形核算、数值积分与谱矩、波高反演、工况档管理和 HTTP 路由拆成互相独立的模块，别把积分和反演糊在同一个大文件里。工况档持久化到容器内即可。仓里放一份 Dockerfile，镜像构建完成后容器一启动就对外提供接口，自动化测试随构建执行，覆盖谱形正算、矩积分收敛、波高反演闭合、γ=1 退化与非法参数拦截。这个后端只做 JONSWAP 频谱的核算与反演，仅经 HTTP 对外服务，不带任何网页界面，也与气象预报、航线规划这类应用无关。
